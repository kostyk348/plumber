Plan 9, 1992 → сегодня

Программа говорит, что у неё за текст.
Правила решают, кто его откроет.

plumber — один демон и один текстовый файл правил вместо интеграций «каждый с каждым». Строка из лога main.rs:42 открывает редактор на сорок второй строке, manual.pdf:7 — документ на седьмой странице, номер детали — каталог. Программы при этом не знают друг о друге.

01Что это даёт

Обычная интеграция — это договор между двумя программами: просмотрщик логов знает про редактор, каталог знает про браузер, и каждая пара пишется руками. Пять программ — двадцать пять связей. Plumber убирает связь: программа отдаёт текст в одно место, а что с ним делать — дело правил.

N×M → N+M

Новый инструмент — это одно правило

Чтобы подключить новый редактор, браузер или каталог, не меняют ни одну программу-отправителя. Правило в файле, читатель порта — и всё. Десять отправителей и десять получателей: было сто интеграций, стало двадцать.

Контекст

Один и тот же текст значит разное

XB-24 — номер детали и идёт в каталог. XB-24.pdf:3 — документ и идёт в просмотрщик PDF на страницу 3. XB-24.rs:11 — файл и идёт в редактор. Решает не отправитель, а правила: тип, содержимое и то, существует ли файл на диске.

Прозрачность

Маршрутизация — это файл, а не код

Что куда попадает, видно в одном текстовом файле: его можно прочитать, обсудить, положить в git и ограничить. Это же и граница безопасности: plumb start — исполняемое содержимое, поэтому запуск команд выключен по умолчанию.

Без агентов

Работает и для человека, и для скрипта

Отправитель — любая программа, которая умеет печатать в сокет: сборка, тест, скрипт, агент. Поэтому сломанная строка из CI открывается в редакторе тем же правилом, что и из лога.

лог main.rs:42 → правило: файл существует? да → data set $file, addr=:42 → порт edit → редактор на строке 42
смета manual.pdf:7 → правило: это PDF → page=7 → порт pdf → pdfcraft --page 7
накладная EPLAN-XB-24 → правило: шаблон детали → порт catalog → каталог
Что именно было потеряно. В Plan 9 это работало на уровне системы: файл /mnt/plumb/send и правила в /lib/plumbing. Со смертью системы идея исчезла, а проблема вернулась — теперь каждый редактор, браузер и каталог договариваются друг с другом заново.

02Как это работает

Три части: сообщение, правила, порты. Сообщение — семь полей, ровно как в plumb(6) 1992 года.

ПолеЧто это
src, dstкто отправил и на какой порт попало (порт выбирают правила, не отправитель)
wdirрабочий каталог отправителя — чтобы относительный путь стал настоящим
typeтип содержимого: text, image, …
attrпары вида addr=:42, page=7 — то, что нельзя выразить в самом тексте
ndataдлина data в байтах — поэтому в тексте бывают переводы строк
dataсам текст
продюсер ──send──▶ plumberd ──правила──▶ порт edit  ──▶ редактор
                            ├───────────▶ порт pdf   ──▶ pdfcraft
                            └───────────▶ порт web   ──▶ браузер

если на порту никого нет:
  правило называет клиента → сообщение ждёт (придерживается) и придёт тому, кто откроет порт позже
  иначе                    → отправитель получает ошибку, как write() в Plan 9

Транспорт — loopback TCP, потому что в Windows нет файлового сервера, который можно смонтировать процессу. Правила перезагружаются по времени изменения файла, так что для правки достаточно текстового редактора.

03Файл правил

Наборы правил разделены пустой строкой. Срабатывает первый набор, у которого совпали все условия, — поэтому частное пишут выше общего. Условия смотрят на сообщение, действия им распоряжаются. 

addr=':([0-9]+)'                       # макрос раскрывается при чтении файла

# страница PDF — раньше файлового правила, потому что manual.pdf:7 тоже «существующий файл»
type is text
data matches '([a-zA-Z0-9_/\-]+\.pdf)('$addr')?'
arg isfile $1                          # а это правда файл на диске?
data set $file                         # тогда заменить текст на разрешённый путь
attr add page=$2                       # а номер страницы — в атрибут
plumb to pdf

# существующий файл со строкой — в редактор
type is text
data matches '([.a-zA-Z0-9_/\-]+[a-zA-Z0-9_/\-])('$addr')?'
arg isfile $1
data set $file
attr add addr=$2
plumb to edit
Объектыsrc dst wdir type attr data arg
Глаголыis isfile isdir matches set add delete
Действияplumb to plumb start plumb client plumb hide
Подстановки$0…$n $file $dir $wdir $src $dst $type

04Попробовать

Три команды: демон, читатель порта, отправитель.

cargo build --release

./target/release/plumberd --rules plumbing.example        # 1. демон
./target/release/plumb-open edit                          # 2. читатель (в другом окне)

./target/release/plumb send "src/main.rs:42"              # 3. отправитель
#   OK edit
#   читатель: would run: code -g src/main.rs:42

./target/release/plumb test --rules plumbing.example "manual.pdf:7"   # без демона: что будет
plumberd

Демон

Слушает loopback, держит порты и читателей, перезагружает правила по mtime. SEND READ PORTS RULES PING — протокол настолько простой, что с ним говорит nc.

plumb

Клиент

Отправить сообщение, читать порт, узнать порты, сухой прогон правил. Сухой прогон — самый быстрый способ отладить сам файл правил.

plumb-open

Открыватель

Читатель, который открывает: цепочка программ по умолчанию на каждый порт, шаблоны {file} {line} {page} {attr:name}, --dry-run.

05Состояние — без прикрас

ЧтоКак есть
Тесты22 зелёных, без моков: формат сообщения, порядок правил, переписывание пути, придержанное сообщение, два end-to-end через реальный сокет
Проверено вживуюда: демон + два читателя + три отправки; manual.pdf:7 → pdfcraft … --page 7
Named pipesнет, транспорт только loopback TCP
Строка без VS Codeтеряется: notepad не умеет переходить на строку — нужен свой --cmd или редактор, который умеет
Мелочипути в правилах пишутся с /; plumb start выключен без --allow-start, потому что файл правил — исполняемое содержимое

06Куда дальше

Named pipes и 9P

Порт без TCP-слушателя — для песочниц; и настоящий файловый сервер там, где файловую систему можно смонтировать.

Правила для своих инструментов

doi: → музей, объекты git → git show, детали EPLAN → каталог, страницы PDF → PdfCraft.

Больше читателей

Читатель — это 60 строк: подписаться на порт и открыть. Писать интеграции больше не нужно — только их читателей.
