plumber.
Обзор Установка Правила Протокол В системе

Установка

Три бинарника,
один текстовый файл

Ставить нечего, кроме plumberd, plumb и plumber-open. Никаких зависимостей во время работы, никаких демонов в системе, о которых вы не просили.

Из исходников

Нужен Rust 1.80 или новее. Сборка — одна команда, зависимостей у самого проекта нет.

git clone https://github.com/kostyk348/plumber
cd plumber
cargo build --release

# положить в PATH
install -m 755 target/release/plumberd \
              target/release/plumb \
              target/release/plumber-open  ~/.local/bin/

Проверка, что всё живо, — без демона и без сокета:

plumb test --rules plumbing.example "src/main.rs:42"
# edit  data="src/main.rs:42"  attr line=42

Готовые бинарники

На теге собираются архивы под все десктопные платформы и прикладываются к релизу рядом с SHA256SUMS:

ПлатформаАрхив
Linux x86-64plumber-linux-x64.tar.gz
Windows x86-64plumber-windows-x64.zip
macOS Apple Siliconplumber-macos-arm64.tar.gz
macOS Intelplumber-macos-x64.tar.gz
 
curl -fLO https://github.com/kostyk348/plumber/releases/latest/download/plumber-linux-x64.tar.gz
sha256sum -c plumber-linux-x64.tar.gz.sha256
tar -xzf plumber-linux-x64.tar.gz
install -m 755 plumber-linux-x64/* ~/.local/bin/

Где что лежит

ЧтоLinux / macOSWindows
Файл с номером порта (его пишет демон, читают клиенты) ~/.plumber/port %LOCALAPPDATA%\plumber\port
Файл правил где скажете: --rules где скажете: --rules
Порт по умолчанию для клиентов берётся из файла порта; переопределяется --port N
Демон сам создаёт каталог для файла порта, но не создаёт файл правил: без --rules он откажется стартовать — молча работать «по каким-то» правилам хуже, чем не работать.

Демон как пользовательский сервис (systemd)

Демону не нужны права root: он слушает loopback и читает один файл. Поэтому — юнит в systemd --user, а не системный сервис. 

mkdir -p ~/.config/systemd/user ~/.config/plumber
cp plumbing.example ~/.config/plumber/plumbing

cat > ~/.config/systemd/user/plumber.service <<'EOF'
[Unit]
Description=plumber — маршрутизация сообщений по правилам
After=default.target

[Service]
Type=simple
ExecStart=%h/.local/bin/plumberd --rules %h/.config/plumber/plumbing
Restart=on-failure
RestartSec=2

[Install]
WantedBy=default.target
EOF

systemctl --user daemon-reload
systemctl --user enable --now plumber.service
systemctl --user status plumber.service --no-pager

Проверка вживую — из соседнего терминала:

plumb ports          # порты из правил и сколько на каждом читателей
plumb send "https://9fans.net"
# OK web
Логи — journalctl --user -u plumber -f. Правила перечитываются по изменению файла: systemctl --user restart после правки не нужен.

Windows и macOS

На Windows демон запускается из ярлыка, из shell:startup или Планировщиком задач: plumberd.exe --rules %USERPROFILE%\.config\plumber\plumbing. Служба не нужна — демон работает в сессии пользователя, потому что открывает программы этой сессии.

На macOS — launchd: ~/Library/LaunchAgents/dev.plumber.plist с ProgramArguments из тех же трёх строк, RunAtLoad и KeepAlive. Загрузить: launchctl load ~/Library/LaunchAgents/dev.plumber.plist.

Проверить, что всё работает

# 1. демон отвечает
plumb ports

# 2. правила разбираются и маршрут находится (без демона)
plumb test --rules ~/.config/plumber/plumbing "src/main.rs:42"

# 3. читатель и отправитель находят друг друга
plumb read edit &          # в одном окне
plumb send "Cargo.toml:1"   # в другом: OK edit

Если третий шаг вернул ERR no reader on port edit — демон жив, правила сработали, просто порт никто не слушает. Это не ошибка установки.
