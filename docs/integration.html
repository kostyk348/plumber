plumber как часть системы

Демон, файл правил и три точки подключения: сервис, обработчики MIME и программы, которые умеют звать plumb send. Ни одна из них не обязательна — но вместе они дают то, чего на десктопе обычно нет.

1. Демон живёт в сессии пользователя

Демон открывает программы от вашего имени, поэтому он и должен работать под вами, а не системной службой: у системного сервиса нет ни дисплея, ни вашего PATH. 

install -Dm644 plumbing.example ~/.config/plumber/plumbing
install -Dm644 /dev/stdin ~/.config/systemd/user/plumber.service <<'EOF'
[Unit]
Description=plumber — маршрутизация сообщений по правилам
After=default.target

[Service]
Type=simple
ExecStart=%h/.local/bin/plumberd --rules %h/.config/plumber/plumbing
Restart=on-failure
RestartSec=2

[Install]
WantedBy=default.target
EOF

systemctl --user daemon-reload
systemctl --user enable --now plumber
systemctl --user is-active plumber      # active
Restart=on-failure и RestartSec=2 — не украшение: демон держит сокет на loopback, и падение без перезапуска означает, что все plumb send в системе начинают молча не работать. Правка правил перезапуска не требует — файл читается по времени изменения.

2. Файл правил — в вашем конфиге, а не в проекте

Правила — это политика машины: что считать ссылкой, чем открывать PDF, куда идёт номер детали. Поэтому они лежат в ~/.config/plumber/plumbing, а не в репозитории отдельного приложения. Репозиторий может положить свои правила рядом и подключить их include. 

# ~/.config/plumber/plumbing
include local              # ~/.config/plumber/local — личные правила, ниже по приоритету

addr=':([0-9]+)'

type is text
data matches '([a-zA-Z0-9_/\\-]+\\.pdf)('$addr')?'
arg isfile $1
data set $file
attr add page=$2
plumb to pdf

type is text
data matches '([.a-zA-Z0-9_/\\-]+[a-zA-Z0-9_/\\-])('$addr')?'
arg isfile $1
data set $file
attr add addr=$2
plumb to edit

Проверять правку — не демоном, а plumb test: он разбирает тот же файл и показывает сообщение, которое получил бы читатель.

3. Обработчик MIME: файл открывается через правила

Это то, чего у plumber в Plan 9 не было и что нужно современному десктопу: файловый менеджер умеет запускать программу по MIME-типу, а программа — просто отправить путь в plumb. Тогда двойной клик и строка из лога идут одним маршрутом.

Ярлык обработчика — обычный .desktop:

# ~/.local/share/applications/plumber-file.desktop
[Desktop Entry]
Type=Application
Name=Открыть через plumber
Exec=plumber-open edit --cmd 'xdg-open {file}'
MimeType=text/plain;text/x-python;text/x-rust;text/markdown;
NoDisplay=false
Terminal=false

update-desktop-database ~/.local/share/applications
xdg-mime default plumber-file.desktop text/plain
xdg-mime query default text/plain      # plumber-file.desktop
Назначать plumber обработчиком по умолчанию для всех текстовых файлов — на любителя: если демон не запущен, файл не откроется вовсе. Разумнее оставить системный обработчик и добавить plumber как вариант в меню «Открыть с помощью», а по умолчанию ставить только для тех типов, где правила действительно знают больше файлового менеджера — например application/x-plumb для ваших собственных ссылок.

4. Терминал и редактор

Отправлять умеет любая строка в терминале. Удобно завести короткие обёртки:

# ~/.bashrc или ~/.zshrc
pl() { plumb send "$*"; }                 # pl https://9fans.net
plf() { plumb send "$1:${2:-1}"; }        # plf src/main.rs 42

Из редактора — одна команда, и она не зависит от того, какой редактор у вас завтра:

ОткудаКоманда
vim / neovim:!plumb send %:p:%l — или :!plumb send "<cword>"
emacsM-! plumb send (buffer-file-name)
любой редактор с внешней командойplumb send "$FILE:$LINE"
tmuxbind-key p run-shell 'plumb send "#{pane_current_path}"'

А в обратную сторону работает plumber-open: он читает порт и запускает программу из шаблона. Это и есть «прыгнуть на строку» — только шаблон задаёте вы, а не автор лога. 

plumber-open edit --cmd 'code -g {file}:{line}'
plumber-open edit --cmd 'gvim +{line} {file}'
plumber-open pdf  --cmd 'zathura -P {page} {file}'

5. Что звать из своих программ

Правило хорошего тона: программа не открывает ничего сама, она сообщает, что у неё за данные. Одна строка вместо интеграции с каждым редактором: 

plumb send "$file:$line"                      # строка из вывода сборки
plumb send "$url"                             # ссылка
plumb send "$pdf:$page"                       # страница документа
plumb send "$part" --type text --src catalog  # номер детали, с указанием источника

Если демона нет, plumb честно вернёт ошибку подключения — вызывающая программа может решить, падать или просто напечатать путь. Это лучше, чем молча ничего не открыть.

6. Безопасность и границы

  • Сокет только loopback. Любой процесс вашего пользователя может отправлять сообщения — но только он. Другого пользователя система не пустит.
  • plumb start выключен. Файл правил — исполняемое содержимое: включение этого глагола означает, что тот, кто правит файл, запускает команды от вашего имени. Включать только с --allow-start и только на своём файле правил.
  • Сообщение — это данные, а не код. Демон не исполняет data; исполняет только то, что написано в правилах, и только если разрешено.
  • Размер кадра ограничен (16 МиБ) и ожидание кадра — тоже (5 с на чтение): зависший клиент не держит поток демона.
  • Никакой телеметрии и сети наружу. Ни одного исходящего соединения, кроме того, что запустит ваш опенер.
