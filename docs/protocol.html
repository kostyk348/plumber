Справочник

Протокол и клиенты

Пять команд по loopback. Клиент можно написать на чём угодно, включая nc: демон говорит строками, сообщение — семь строк с длиной перед данными.

Команды

КомандаОтветЧто делает
SEND nOK порт или ERR причинаследом идут n байт сообщения; демон прогоняет его по правилам
READ портпоток сообщенийподписаться на порт; дальше в соединение идут сообщения с длиной перед каждым
PORTSпорт N на строкупорты из правил и число читателей на каждом
RULESтекст файла правилчто демон на самом деле разбирает сейчас
PINGPONGжив ли

Соединение одноразовое: команда, ответ, закрытие. Никакого состояния между запросами, никакого рукопожатия, никакой версии протокола — всё, что можно сделать неправильно, здесь просто не предусмотрено.

Формат сообщения

Ровно как в plumb(6): строки, атрибуты строкой, затем длина и данные.

src            # кто отправил
dst            # на какой порт попало (ставит демон)
wdir           # рабочий каталог отправителя
type           # text, image, …
attr           # пары k=v через пробел; пробелы и кавычки — в "…"
ndata          # длина data в байтах
data           # сам текст (может содержать переводы строк)

Пример на проводе — то, что уходит в сокет при plumb send "src/main.rs:42":

plumbd
edit
/home/you/project
text
addr=:42

29
/home/you/project/src/main.rs
Длина data — в байтах, а не в символах: сообщение с эмодзи или кириллицей занимает больше байт, чем выглядит. Это то место, где самодельные клиенты ломаются чаще всего.

Клиент на shell

Демон слушает 127.0.0.1, порт лежит в ~/.plumber/port.

PORT=$(cat ~/.plumber/port)
printf 'PING\r\n' | nc 127.0.0.1 "$PORT"
# PONG

printf 'PORTS\n' | nc 127.0.0.1 "$PORT"
# edit 1
# web 0

Отправка без plumb — считаем длину сами:

msg=$'whoami\nedit\n'"$PWD"$'\ntext\n\n5\nhello'
printf 'SEND %d\n%s' "${#msg}" "$msg" | nc 127.0.0.1 "$(cat ~/.plumber/port)"

Это работает для ASCII. Для UTF-8 считайте байты, а не символы: plumb и plumber-open уже это делают.

Клиент на Python

Сорок строк — полноценный читатель порта, который переживает обрыв соединения.

import socket, pathlib

def port():
    return int(pathlib.Path.home().joinpath(".plumber/port").read_text().strip())

def frames(sock):
    f = sock.makefile("rb")
    while True:
        line = f.readline()
        if not line:
            return
        n = int(line.strip())
        yield f.read(n).decode("utf-8", "replace")

s = socket.create_connection(("127.0.0.1", port()))
s.sendall(b"READ edit\n")
for message in frames(s):
    src, dst, wdir, kind, attr, ndata, data = message.split("\n", 6)
    attrs = dict(p.split("=", 1) for p in attr.split() if "=" in p)
    print(f"{data} {attrs.get('addr', '')}")

Что умеют программы

plumb

plumb send <text> [--src NAME] [--type text] [--wdir DIR] [--port N]
plumb read <port> [--port N]
plumb rules | plumb ports [--port N]
plumb test --rules FILE <text> [--wdir DIR]      # без демона

plumber-open

plumber-open <port> [--cmd 'ШАБЛОН'] [--port N] [--dry-run] [--once]
ПортКандидаты команд (первый найденный в PATH)
editcode -g {file}:{line} → code {file} → notepad {file}
webcmd /c start "" {data} → xdg-open {data}
pdfpdfcraft {file} --page {page} → cmd /c start "" {file} → xdg-open {file}
scenecadcraft {file}

Подстановки в шаблоне: {data} {file} {line} {page} {addr} {dir} {attr:имя}. Свой шаблон заменяет весь список кандидатов:

plumber-open edit --cmd 'gvim -c {line} {file}'
plumber-open pdf  --cmd 'zathura -P {page} {file}'

# что запустилось бы — ничего не запуская
plumber-open edit --dry-run
--dry-run — самый быстрый способ проверить, что правило и опенер сходятся: он печатает готовую команду и не трогает ни один процесс.

Ошибки, которые видит отправитель

ОтветЧто значит
ERR no rule matched this messageни один набор правил не совпал — сообщение выброшено. Это не сбой, а решение правил.
ERR no reader on port Xправило сработало, но на порту никого нет и клиент не назван — отправитель должен узнать об этом, как write() в Plan 9.
ERR unknown command (…)демон не понял строку команды; в скобках перечислено, что он понимает.

Если правило называет клиента (plumb client), ошибки не будет: сообщение придерживается внутри демона и уходит первому, кто откроет порт. Это единственное место, где демон что-то помнит, и эта память не переживает его перезапуск.
